MySQL protocol server

See MySQL functions for scalar, string, numeric, temporal, encoding, session and utility function coverage and compatibility boundaries.

SlopDB can serve an existing database directory to MySQL clients over TCP, a Unix socket, or both. MySQL sessions enable the supported MySQL type, expression and affected-row rules; native API sessions retain SlopDB semantics. One process owns the database; use client connections instead of opening that directory from another process while the server is running.

go build -o slopdb .
./slopdb --mysql-tcp 127.0.0.1:3306 ./example-db
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u slopdb slopdb

For Unix sockets, or both transports together:

./slopdb --mysql-socket /tmp/slopdb.sock ./example-db
mysql --protocol=SOCKET --socket=/tmp/slopdb.sock -u slopdb slopdb

./slopdb --mysql-tcp 127.0.0.1:3306 --mysql-socket /tmp/slopdb.sock ./example-db

Specifying either listener flag starts server mode, without reading SQL from stdin. Unix sockets are created with permissions 0600 and removed on clean shutdown. An existing socket or file is never removed to make room for a new listener. Remove a stale socket yourself after verifying its server has stopped. Listener startup errors close any listeners already created and exit nonzero. SIGINT and SIGTERM disconnect clients, cancel queries, roll back pending transactions, and close and flush the database. Flush failures exit nonzero.

The default login is slopdb with an empty password; the exposed database name is slopdb. Set a password without placing it in command-line arguments:

export SLOPDB_MYSQL_PASSWORD='choose-a-password'
./slopdb --mysql-tcp 127.0.0.1:3306 \
  --mysql-user app --mysql-database app \
  --mysql-password-env SLOPDB_MYSQL_PASSWORD ./example-db
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u app -p app

A named password environment variable must exist; an explicitly empty value permits passwordless login. Authentication uses mysql_native_password. There is a configured bootstrap account with full access. CREATE USER, ALTER USER, DROP USER, GRANT, REVOKE and SHOW GRANTS manage persistent additional accounts. Permission checks are currently disabled: authenticated accounts can access all schemas. Grant metadata remains available for compatibility. Password hashes and grant metadata share the database's normal WAL durability. The bootstrap account remains configured by startup flags and cannot be changed through SQL. Supported account hosts are exact addresses, localhost (including loopback TCP), and %; authentication uses mysql_native_password. TLS and client certificate checks apply to all accounts. The protocol reports MySQL compatibility version 5.7.44-SlopDB, including the handshake, VERSION(), and session/global version variables.

Server mode enables MySQL quoting by default. Pass --mysql-quoting=false to use SlopDB's ordinary quoting rules. Other CLI storage, query timeout, lock timeout, compression and durability flags apply normally; WAL and WAL fsync remain enabled by default.

TLS and client certificate authentication

The server supports MySQL's SSLRequest negotiation with TLS 1.2 and 1.3 over both TCP and Unix sockets. Supply a PEM server certificate chain and matching private key to enable TLS. Add --mysql-require-tls to reject plaintext logins:

./slopdb --mysql-tcp 127.0.0.1:3306 \
  --mysql-tls-cert server-chain.pem --mysql-tls-key server-key.pem \
  --mysql-require-tls ./example-db

Without --mysql-require-tls, a server configured with only a certificate/key accepts both encrypted and plaintext connections. Without any TLS configuration, it accepts plaintext connections and does not advertise TLS.

To require a client certificate signed by a specific CA, add --mysql-tls-ca:

./slopdb --mysql-tcp 127.0.0.1:3306 --mysql-socket /tmp/slopdb.sock \
  --mysql-tls-cert server-chain.pem --mysql-tls-key server-key.pem \
  --mysql-tls-ca client-ca.pem ./example-db

mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u slopdb \
  --ssl-mode=VERIFY_IDENTITY --ssl-ca=server-ca.pem \
  --ssl-cert=client-chain.pem --ssl-key=client-key.pem slopdb

--mysql-tls-ca is the server's trust bundle for client certificates. It implies required TLS and required certificate verification on every connection, including Unix sockets. Plaintext cannot bypass certificate authentication. Only chains trusted by that bundle are accepted; system roots are not added. Certificates must be within their validity period and valid for client authentication. Clients should send any intermediate certificates in their certificate chain. The client's --ssl-ca, in contrast, trusts the server certificate, whose DNS name or IP SAN must match the connection hostname. The two CA bundles can contain different issuers.

A verified certificate is an additional login requirement. Clients must still use the configured username and password. To use certificate authentication without a password, leave the server password empty and provide a trusted client certificate. Any valid certificate trusted by the configured client CA can access the configured account; subjects are not mapped to separate accounts.

Certificate/key flags must be supplied together. A client CA or required TLS without a server certificate/key is an error, as are unreadable certificates, mismatched keys and an invalid CA PEM file. These CLI errors are reported before opening the database or creating listeners. Certificates and trust bundles are loaded at startup; restart the server to change them. The authentication timeout covers SSLRequest, TLS negotiation and the encrypted MySQL login. Shutdown also interrupts incomplete TLS handshakes.

Queries and connections

Each authenticated connection owns an independent SlopDB session. Supported commands include text queries, ping, database selection, binary prepared statements with typed parameters, long parameter data, statement reset/close, and connection reset. Results carry column metadata, NULLs, binary values, affected-row counts, generated IDs and transaction status. CLIENT_FOUND_ROWS selects matched-row counts; ordinary MySQL updates report changed rows.

CREATE DATABASE / CREATE SCHEMA create virtual namespaces inside the same physical LSM. USE changes a connection's default namespace, including inside a transaction; qualified names support cross-schema queries and mutations. The configured initial database aliases main. PostgreSQL clients can use CREATE SCHEMA and SET search_path. A database backup includes all namespaces. Existing child databases under mysql-databases/ are imported at MySQL startup using resumable typed batches and durable completion markers. Original sources are preserved. Import rejects differing database-wide collations rather than changing comparison semantics silently.

BEGIN / START TRANSACTION, COMMIT, ROLLBACK and savepoints use the normal SlopDB transaction implementation. Disconnect and connection reset discard uncommitted writes. SET [SESSION] autocommit=0 starts transactions lazily; COMMIT and ROLLBACK finish them, and the next SQL statement starts a new one. Setting autocommit back to 1 commits pending work. The default is autocommit. MySQL sessions default to REPEATABLE READ. Plain SELECTs use a snapshot established by the first consistent table read; START TRANSACTION WITH CONSISTENT SNAPSHOT establishes it immediately. Locking reads and mutations, including their subqueries, read current committed data plus private writes. Own writes remain visible to consistent reads. SET [SESSION] TRANSACTION ISOLATION LEVEL READ COMMITTED or REPEATABLE READ changes the session default; unqualified SET TRANSACTION changes the next transaction. There are no gap locks or SERIALIZABLE isolation. DDL follows SlopDB's transactional behavior and does not implicitly commit an explicit transaction.

Replicated commits include slopdb_commit_position in the OK packet's info field and, when CLIENT_SESSION_TRACK is negotiated, its system-variable state block. SHOW LAST COMMIT POSITION, SHOW REPLICATION POSITION and prepared WAIT FOR POSITION ? TIMEOUT ? expose the same logical-position workflow. See logical commit positions. The framing follows the MySQL OK packet specification.

SET READ BARRIER PREVIOUS / NEXT select certified historical data for reads; DEFAULT restores the node default and COMMITTED restores ordinary admission. See durable read barriers.

Client helpers include SHOW DATABASES, DATABASE(), VERSION(), CONNECTION_ID(), CURRENT_USER(), SHOW [GLOBAL] VARIABLES [LIKE ...], @@GLOBAL.read_only, and common session variable reads. SET supports multiple assignments atomically for autocommit, group_concat_max_len, sql_mode, and UTF-8 character settings. The supported mode flags are STRICT_TRANS_TABLES, STRICT_ALL_TABLES, and NO_AUTO_VALUE_ON_ZERO; an empty mode enables supported nonstrict conversions. Unknown variables or unsupported mode flags fail. SHOW WARNINGS, @@warning_count and protocol warning counts expose conversion warnings.

net_read_timeout and net_write_timeout are connection-local transfer timeouts in seconds (defaults 30 and 60). SET updates are atomic and reset restores the defaults. They bound stalled partial packets and writes, including TLS and compressed connections; an idle connection waiting for its next command is not closed by the read-transfer timeout.

GET_LOCK(name, timeout), IS_FREE_LOCK(name) and RELEASE_LOCK(name) use real connection-owned, reentrant named locks across sessions. Waits block with deadlines and cancellation; disconnect/reset releases all owned locks. MySQL-session EXPLAIN SELECT returns MySQL-shaped planner metadata without executing the query.

SHOW ENGINES advertises the native transactional LSM engine. Table ENGINE= clauses are ignored; SHOW TABLE STATUS and information_schema.tables identify LSM storage. No alternate storage engine is selected by portable MySQL schemas. Other queries run through the native SQL engine, including SHOW, DESCRIBE and introspection. The supported virtual system tables are information_schema.schemata, tables, columns, user_privileges, schema_privileges, and a compatibility mysql.user view of account names and hosts.

Prepared parameters use anonymous ? placeholders. Preparation returns parameter and result metadata by inspecting the bound catalog and expression types, without executing the statement or evaluating user expressions. Prepared statements retain their preparation namespace. Catalog changes invalidate cached plans and metadata. Negotiated multi-statements return one result per statement, stop at the first failure, and set the protocol's more-results flag. COM_SET_OPTION can toggle multi-statements. Standard zlib protocol compression uses independently sequenced, bounded compressed frames and works with TLS. MySQL cursors, LOCAL INFILE, stored procedures and general administrative MySQL commands remain unsupported.

SlopDB validates stored column types. MySQL sessions convert wire strings to BLOBs for binary columns, including empty values. Native API sessions retain strict BLOB affinity. SQL BLOB literals such as X'00ff' also work. Signed int64 and unsigned uint64 parameters, rows and generated IDs retain their complete ranges. DECIMAL values use exact decimal arithmetic and NEWDECIMAL wire metadata; JSON uses validated JSON storage, JSON functions/path accessors and JSON wire metadata. Declared MySQL integer widths, unsigned flags, FLOAT, DATE/DATETIME/TIMESTAMP, fixed BINARY and ENUM are reflected in result metadata and binary prepared rows. Native REAL values retain float64 precision on the wire. Mixed-type expression columns use a string wire type to preserve their values without rounding large integers.

The endpoint can act as a MySQL replication source with a durable LSM-backed CDC journal, full row events, GTIDs, byte-position resume, checksums and heartbeats. See MySQL CDC for activation, initial snapshots and DDL boundaries.

Go clients and embedding

A standard MySQL driver can connect with a DSN such as:

slopdb@tcp(127.0.0.1:3306)/slopdb
slopdb@unix(/tmp/slopdb.sock)/slopdb

For embedding, package slopdb/mysqlserver accepts caller-created listeners:

server, err := mysqlserver.New(database, mysqlserver.Config{
    Username: "app", Password: password, Database: "app",
})
if err != nil { return err }
defer server.Close()
listener, err := net.Listen("tcp", "127.0.0.1:3306")
if err != nil { return err }
return server.Serve(listener)

Call Serve concurrently with separate TCP and Unix listeners to expose both. Server.Close closes its listeners and clients and waits for session cleanup; the caller then closes the database and checks its flush error. The caller controls Unix socket permissions when embedding. Default limits are 64 MiB per incoming logical packet or accumulated long parameters, 1,024 prepared statements per connection, and 10 seconds to authenticate. mysqlserver.Config can override these limits.

Embedded servers enable TLS with mysqlserver.Config.TLSConfig, a *tls.Config containing server certificates, and can set RequireTLS: true. For mutual TLS, set TLSConfig.ClientAuth = tls.RequireAndVerifyClientCert and set TLSConfig.ClientCAs to an explicit x509.CertPool. This automatically requires TLS, even when RequireTLS is false. New clones the TLS configuration and CA pool and enforces a minimum of TLS 1.2. GetConfigForClient is unsupported so dynamic configurations cannot override the verification policy; use GetCertificate for certificate selection. Embedded servers retain their database's existing SQL quoting options.
