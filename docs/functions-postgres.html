PostgreSQL functions

Function inventory verified against the supplied SlopDB source checkout 0051985. Entries document implemented behavior, including compatibility placeholders and restrictions.

← Search all SQL functions · 150 documented names/forms in this family.

These functions and overrides run in PostgreSQL mode on the same SlopDB engine. They do not imply complete PostgreSQL SQL, types, catalogs, permissions, or extension support. See compatibility coverage and server operation.

Types and inherited behavior

The registry includes all listed aliases. NULL rules differ from MySQL for names such as CONCAT. Numeric transcendental functions currently use double precision even for NUMERIC inputs. RANDOM is inherited from the native engine and returns an integer; SETSEED is unsupported. Native functions outside these overrides can retain native behavior. General SQL arrays and set-returning functions are not implemented.

Clocks and formatting

Transaction-clock functions stay stable through statements and savepoints in an explicit transaction. STATEMENT_TIMESTAMP uses statement time; CLOCK_TIMESTAMP and TIMEOFDAY read the wall clock. Most clock output uses UTC. Date templates support common calendar/time fields such as YYYY, MM, DD, HH24, MI, SS, MS, US, and supported timezone fields; broad PostgreSQL numeric/interval formatting, input normalization, locale behavior, and BCE/large-year dates are not promised.

Regex and JSON paths

Regex uses RE2 with a supported PostgreSQL flag subset, including i/c and supported newline/expanded controls; g selects global replacement. Unsupported flags and constructs fail. JSON path arguments such as '{a,0}' are textual path arrays, not a general SQL array type. JSON builders preserve SQL booleans and exact numbers and distinguish SQL NULL from JSON null.
