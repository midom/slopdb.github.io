MySQL functions

MySQL function validation, execution, prepared-result metadata and optimizer volatility share a function registry. Functions work in expressions, predicates, prepared statements and persisted views/defaults where those expressions are allowed. Native SQLite-style functions retain their existing behavior outside MySQL mode; MySQL sessions use MySQL-specific LENGTH, HEX, ROUND and ABS rules.

SQL forms include POSITION(x IN y), SUBSTRING(x FROM n FOR count), TRIM(BOTH x FROM y), CHAR(... USING utf8mb4), EXTRACT(YEAR_MONTH FROM value) and DATE_ADD(value, INTERVAL n MONTH). Canonical persisted expressions reparse through the same function validation.

Behavior

TEXT string positions count Unicode code points; BLOB operations count bytes. Function-specific NULL and binary-result rules are preserved. UTF-8 charset aliases utf8, utf8mb3 and utf8mb4 all accept full Unicode, as elsewhere in SlopDB. Invalid UTF-8 conversions still fail. Explicit collations and SlopDB's configured text collation continue to control comparisons.

DECIMAL rounding and truncation stay exact, including values beyond float64's integer precision. Exact decimal ROUND ties round away from zero; approximate DOUBLE ties use nearest-even. Scientific literals remain approximate in MySQL mode. Integer arguments distinguish exact numbers, approximate numbers and integer prefixes of strings. FORMAT supports the documented MySQL locale names, with checked-in punctuation/grouping answers from an independent MySQL server.

Calendar arithmetic clamps month-end dates, handles leap years and supports all eight WEEK modes. Time arithmetic preserves signed durations up to the MySQL 838-hour range and handles fractional seconds. The session timezone remains UTC. Temporal results use SlopDB's existing TEXT representation.

RAND uses MySQL's seed/generator rules. Constant seeded expressions advance privately across rows; column-dependent seeds are applied per row. Statement state is released after success or failure and prepared executions start a fresh seeded sequence. Random, clock, locking, session and blocking functions are classified as volatile, preventing constant caching or unsafe predicate reuse.

LAST_INSERT_ID records the first generated ID of a multi-row insert, preserves uint64 values, ignores explicitly assigned IDs, isolates trigger changes and survives transaction rollback. LAST_INSERT_ID(expr) updates the connection value. ROW_COUNT reports affected rows or -1 for a result-producing statement. FOUND_ROWS reports the preceding SELECT's returned row count; SQL_CALC_FOUND_ROWS is not implemented. SLEEP waits on a timer; SLEEP and BENCHMARK honor native query cancellation and deadlines.

Generated strings, padding, formatting and decompression check the query memory budget before allocating expanded results. Invalid arities fail even on empty inputs. Hashes and UUID/IP conversion return text or binary values with matching prepared metadata. AES functions currently implement MySQL's default aes-128-ecb behavior and padding; other block modes and KDF arguments are not implemented. COMPRESS uses MySQL's length-prefix/zlib format and reads MySQL compressed values; compressed byte sequences may differ between zlib encoders.

Regular-expression functions support character positions, occurrence selection, capture replacements and match flags, with a bounded statement-local compiled pattern cache. They use RE2. Lookarounds and pattern backreferences produce an unsupported-pattern error. Unicode line-ending and end-anchor rules retain RE2 semantics; anchored SUBSTR/REPLACE patterns at a noninitial position are rejected. This is not a complete implementation of MySQL's ICU regular-expression engine.

Verification and boundaries

Permanent tests cover NULLs, Unicode and binary values, exact decimals, uint64, coercion, prepared calls, metadata, cancellation, memory budgets and persisted views. Oracle MySQL 8.0.46 supplies independent fixed and generated reference answers. The normal suite uses checked-in answers; it does not require MySQL. The independent scalar fixture covers 360 cases through both text and prepared MySQL protocol execution. Regenerate it against an isolated Oracle MySQL server using scripts/regenerate_mysql_function_references.py --socket /path/to/socket. The generator obtains answers only from that server.

This is an implementation of the listed functions, not a complete emulation of every MySQL function, sql_mode, warning, collation or temporal coercion. Native invalid-value, overflow and cancellation policies remain in effect where noted. CONVERT_TZ, locale-dependent date-name settings, automatic numeric-context conversion of temporal TEXT values, uncommon year-zero arithmetic and additional cryptographic modes remain outside this function set.
