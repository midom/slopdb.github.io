JSON functions

Function inventory verified against the supplied SlopDB source checkout f426887. Entries document implemented behavior, including compatibility placeholders and restrictions.

← Search all SQL functions · 28 documented names/forms in this family.

The shared JSON family works with native JSON values and JSON document text. The JSON and JSONB conversion names use the native JSON representation. PostgreSQL adds its own builder/access/update functions; see the PostgreSQL reference.

Documents, values, and paths

Malformed documents and invalid paths fail, except JSON_VALID reports invalid document text as zero. SQL NULL and JSON null are distinct: SQL NULL usually propagates, while builders can embed it as JSON null. Ordinary SQL text is inserted as a JSON string; use JSON(text) to embed a document.

Paths start at $ and support object members, quoted member names, zero-based array indexes, last/last-N, and supported wildcards/recursive descent for reads. Modifying paths reject wildcards. Paths are bounded to 128 components. A missing path and a selected JSON null can have different results depending on the function.

SELECT JSON_SET('{}', '$.items', JSON('[1,2]'));
SELECT JSON_EXTRACT('{"items":[1,2]}', '$.items[0]');

Operator forms

-> returns JSON and ->> returns text. PostgreSQL-style #> and #>> use a textual path array such as '{a,0}'. Missing targets return SQL NULL. These operator forms are syntax over the JSON evaluator, not additional user-callable function names.
