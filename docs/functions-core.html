Core SQL functions

Function inventory verified against the supplied SlopDB source checkout 49150cf. Entries document implemented behavior, including compatibility placeholders and restrictions.

← Search all SQL functions · 30 documented names/forms in this family.

These are the native scalar functions. They work in expressions, predicates, prepared statements, and supported stored expressions. PostgreSQL overrides and MySQL mode can change the behavior of the same name; follow the dialect-specific references when connecting through those listeners.

Inputs, NULL, and comparisons

Function names are case-insensitive. Optional arguments are shown in brackets; ellipses mean repetition. NULL behavior is documented per entry. Conditional functions evaluate only the selected branch. Scalar MIN/MAX take two or more arguments; the one-argument form is a grouped aggregate. Comparisons follow the active text collation.

Native time modifiers

DATE, TIME, DATETIME, JULIANDAY, and STRFTIME accept supported ISO-like dates/times, the word now, or numeric Julian days. Modifiers apply left to right: start of day, start of month, start of year, utc, localtime, weekday N, and signed amounts of days, hours, minutes, seconds, months, or years. Here weekday N means the next matching weekday (Sunday=0), advancing seven days if already on that weekday. Calendar month/year arithmetic follows the native implementation rather than promising SQLite equivalence.

SELECT DATE('2026-01-15', 'start of month', '+1 month');

Conditional values

COALESCE(value, value, ...)

Returns selected value

Returns the first non-NULL argument; later arguments are not evaluated after a value is found. At least two arguments are required.

SELECT COALESCE(NULL, 'ready');

Strings and binary values

HEX(value)

Returns TEXT

Returns uppercase hexadecimal input bytes. Numeric inputs are encoded from their text representation. Native NULL produces an empty string; MySQL-mode NULL remains NULL.

Numeric inputs currently retain native textual-byte conversion in MySQL mode too; this is not complete MySQL numeric HEX equivalence.

SELECT HEX('Go');

Returns TEXT or BLOB

Slices TEXT by Unicode code point or BLOB by byte. Positions are one-based; negative starts count from the end. A negative length selects characters preceding the start.

Numbers and conversion

ABS(number)

Returns numeric

Returns absolute numeric value, preserving integer or exact numeric representation where supported. NULL propagates; nonnumeric input and signed integer overflow fail.

MySQL and PostgreSQL sessions provide their own coercion and metadata rules.

SELECT ABS(-12);

CAST(value AS type)

Returns target type

Converts to a supported SQL type with the active dialect’s conversion, precision, range, and length checks. NULL remains NULL.

Use SQL AS syntax, not CAST(value, type). PostgreSQL also supports :: casts. See SQL semantics and the protocol guides for type coverage.

SELECT CAST('42' AS INTEGER);

RANDOM()

Returns INTEGER

Returns a nonnegative pseudo-random signed 64-bit integer. It is not a cryptographic random-byte generator.

PostgreSQL mode retains this native integer behavior; use RAND for a MySQL-style real result.

SELECT RANDOM();
Source: sql/executor.go · 49150cf

ROUND(number [, digits])

Returns numeric

Rounds a numeric value; digits defaults to zero. Native digits are clamped to 0 through 30. Integer/real inputs use floating-point rounding; exact DECIMAL inputs retain decimal arithmetic.

MySQL supports negative digit counts and different exact/approximate tie rules. PostgreSQL uses a separate numeric implementation.

SELECT ROUND(12.345, 2);

Native date and time

DATE([timestring [, modifier, ...]])

Returns TEXT

Formats a parsed value as YYYY-MM-DD, HH:MM:SS, or YYYY-MM-DD HH:MM:SS. No argument, an empty string, or now reads the current UTC clock.

Numeric input is a Julian day, not Unix seconds. Invalid or NULL timestrings fail. These are native helpers, not complete SQLite/MySQL temporal emulations.

SELECT DATE('2026-01-02 03:04:05');

Full-text search

FULLTEXT_MATCH(column, search [, mode])

Returns REAL · requires session or schema setup

Returns the shared full-text relevance score using an appropriate FULLTEXT index. Index configuration, including tokenizer, normalization, stopwords, token bounds, and ranking, is persisted and reused across native, MySQL, and PostgreSQL sessions.

Create an articles table and a FULLTEXT index on body before running this example. MySQL MATCH/AGAINST is a syntax adapter over the same engine; see SQL semantics for index configuration.

SELECT id, FULLTEXT_MATCH(body, 'slime') AS score FROM articles;
