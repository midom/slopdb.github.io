SLOPDB / DOCUMENTATION / TESTS

Tests

Run from the repository root:

go build -o slopdb .
go test ./...
go test -race ./...
go vet ./...

The Go tests include the regression and functionality checks previously kept as standalone programs. They use isolated temporary directories, close databases on failure, and work from a fresh checkout. Concurrent invocations do not share database paths. Test names can be selected with the normal -run flag:

go test ./tests/regression -run 'Test(Join|Prepared|SQL|Execution)' -v
go test -race ./tests/regression -run 'Test(Concurrent|IndexedMVCC|BatchTransactions|ForeignKey)' -v
go test ./sql -run TestMalformedParserInputs
go test ./sql -run '^$' -fuzz FuzzParse -fuzztime 30s

The SQL reference tests execute 599 semantics queries, 98 execution queries, and 1,797 join/index/LIKE queries both before and after reopening: 4,291 reference checks. The parser tests also cover 15,000 deterministically generated inputs. Other suites include 2,071 prepared API checks, 4,000 indexed concurrent updates, 32-worker atomic transaction checks, and 320,000 concurrent memtable insertions. These are functional assertions; no test requires achieving a machine-dependent throughput or latency score.

Additional suites cover CTEs and recursive guardrails, UPSERT constraints and concurrency, 51 independent window reference queries, prepared-plan invalidation, distribution statistics, actual EXPLAIN ANALYZE counters, bounded access, operator spilling and cleanup, streaming cursor ordering, bulk import, online backup and integrity checks. Cross-feature tests exercise prepared CTE/window/ UPSERT execution and lexical CTE scopes in optimized subqueries. See integrated improvements and performance checks.

Crash recovery uses a separate instance of the Go test executable that deliberately exits without closing the database. CLI tests build the current CLI into a temporary directory automatically, including -race when the test suite uses the race detector. Linux terminal/SIGTERM checks use a pseudo-terminal. Actual fsync syscall verification runs when Linux strace is installed; otherwise that additional test is skipped. WAL recording, replay, durability modes and error checks still run without strace.

The command-line implementation and its unit tests live in internal/cli/. The root main.go delegates to that package, so plain go build from the repository root still produces the slopdb executable.

Reference fixtures

The SQLite answers and their setup SQL are checked into tests/regression/testdata. Running Go tests requires neither Python nor SQLite/DuckDB installations. To independently recompute answers, use Python's standard-library SQLite driver:

python3 tests/regression/testdata/regenerate_references.py
go test ./tests/regression -run 'Test(SQLDifferential|ExecutionDifferential|JoinDifferential)$'

To also regenerate the deterministic join/LIKE query set and inputs:

python3 tests/regression/testdata/generate_join_cases.py
python3 tests/regression/testdata/regenerate_references.py

Numeric comparisons preserve exact int64 values; REAL answers use an absolute tolerance of 1e-8. Queries preserve their saved result order. Changes to fixtures should be reviewed as SQL behavior changes, rather than replacing expected values with SlopDB's own output.

The migration updates old godb/... imports and standalone panic/exit handling for the current Go test runner. Diagnostic index repair explicitly uses VerifyIndexesOnOpen; ordinary opens trust maintained indexes. Superseded duplicate programs, old nullable-primary-key/loose-type expectations, removed index-maintenance markers and deprecated compression options are not current regression requirements.

Benchmarks and engine comparisons

Large DBGEN inputs, profiling scripts and benchmark result archives are separate from the ordinary test suite. The existing TPC-H runner, TPC-C load tester and cross-engine TPC-C runner document their inputs and commands. The native comparison runners live in nested Go modules and have their own Go/CGO requirements; go test ./... covers the root module without installing those drivers.

Catalog performance benchmarks are in db/catalog_benchmark_test.go. See catalog measurements for isolated point SELECTs, profile findings, concurrency settings and saved source fingerprints.

Raft replication tests live in replication/: TCP/Unix seed snapshots, nonvoter catch-up/promotion, leadership transfer/failover, minority rejection, durable restart and duplicate replay, offline snapshot installation, concurrent writes, corruption/truncation rejection and mutual TLS. replication/roles_test.go covers permanent nonvoters, rejected promotion, nonvoter reads and restart, two full copies plus a logs-only voter over TCP/Unix in sync/async modes, failover, quorum writes, restart, role identity, election and direct-transfer exclusion, metadata-only application and recovery from a journal after full-node payload loss. replication/durability_test.go covers async/durable commit, periodic flushing, lag admission, certificate validation, recovering voters and all-cold recovery after removing volatile log suffixes and application generations. Wire tests cover prepared durable commits and unknown confirmation outcomes on both SQL protocols. tests/regression/replication_async_linux_test.go uses SIGKILL and the offline CLI recovery procedure to check stable-prefix restoration. When strace is available, replication/durability_syscall_linux_test.go checks that async commits skip WAL fsync and explicit durable barriers issue it. replication/read_index_test.go covers reads without log appends and cancellation while committed entries await native application. Replica-read tests cover TCP/Unix and sync/async modes, prepared/streamed reads, catalog changes during pinned streams, read-only transactions, rejected writes/locks, proof expiry, application backlog/cancellation, restart discovery, leadership transitions and lost quorum. The same read-index flow runs over mutual TLS, and wire tests exercise MySQL/PostgreSQL prepared reads and stale-read failures. SQL tests check conservative classification of nested queries, CTEs and windows. Durable-read tests exercise PREVIOUS/NEXT over TCP/Unix, sync/async modes, MySQL/PostgreSQL prepared execution and mutual TLS. A held remote prepare proves that later rows/catalog changes are excluded from a captured fence, including after VACUUM. Tests cover idle NEXT requests, streaming/materialized snapshots, minimum-position conflicts, private-write rejection, missing-view errors, bounded candidate retention, cancellation after Raft enqueue, replica re-cloning, and returning to live prepared writes. Storage tests transfer a global snapshot pin to a statement reader and verify survival through full compaction. Position tests check master/session queries, commit responses, concurrent-commit coverage, delayed native application, explicit/prepared waits, deadline/cancel handling, minimum-position Exec/streaming reads, full-width indexes, tampered and wrong-incarnation tokens, log compaction and stable-point recovery. Raw wire tests decode MySQL plain/session-tracked OK metadata and PostgreSQL simple and extended implicit-commit ParameterStatus; integration tests use both drivers. The quorum-flush pipeline test holds a remote prepare request and verifies later writes can commit without being included in the earlier durable certificate or losing their lag timestamp. Application batching tests cover ordered range deletions, configuration and page-size boundaries, replay, reopen, oversized atomic commands and failed suffixes. Log-codec tests cover mixed legacy/binary records, timestamps, malformed framing, history hashes and caller ownership. Transaction-control tests verify that data access still checks a quorum and commit cannot succeed without one. replication/command_json_test.go checks byte-for-byte standard JSON compatibility, legacy/malformed representations, ownership and checkpoint integer boundaries. FuzzCommandJSONCompatibility compares the decoder with Go's standard library. Proposal-gate tests cover independent enqueue progress, exclusive flush barriers and the limit on unresolved large commands. BenchmarkRaftHotRowTransactions reuses the transaction-throughput fixture with every session updating row 1, measuring write contention through commit. It checks the exact shared-row total, untouched rows, replica equality, integrity and restart/stable recovery outside timing, as does BenchmarkRaftTransactions for independent rows. BenchmarkRaftLogsOnlyTransactions uses the same fixture and explicit prepared transactions with one full node and two logs-only voters. It checks membership, exact totals, and independently rebuilds each journal's snapshot plus WAL into a full SQL database for integrity checks, then verifies cold restart/stable recovery outside timing. Select matching raft3/raft3-async worker counts in BenchmarkRaftTransactions for the three-full-node baseline. Put TMPDIR on a disk filesystem for fsync measurements; test has a RAM-backed /tmp. Use a short temporary path when also running Unix socket tests. See the disk-backed journal-voter measurements for a matched matrix with source fingerprints and per-run results. For one-case diagnostics, -raft-bench-latencies writes per-transaction stage timings, -raft-bench-trace records the timed execution window, and -raft-bench-contention writes timed block/mutex profiles. Keep their paths outside the repository and use one sample per invocation. See the tail-latency investigation for measured waits, syscall evidence and isolated diagnostic controls. tests/regression/replication_linux_test.go exercises CLI MySQL/PostgreSQL replication through SIGKILL/restart and SIGTERM, plus durability flag validation. internal/wire/listen_test.go checks stale Unix socket recovery and preservation of live sockets and regular files. All artifacts use t.TempDir().
