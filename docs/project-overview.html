SlopDB

SlopDB is an embedded SQL database written in Go. It provides a SQLite-like SQL dialect, concurrent transactions, a Go API and an interactive command-line interface, plus optional MySQL and PostgreSQL protocol servers over TCP and Unix sockets. Each database lives in a directory and runs without an external database server.

Features

Queries and data

  • SQL querying for application lookups, reporting and analysis.
  • Data validation and relational integrity, with text and binary data support.
  • Unicode-aware text comparison and optional case-insensitive matching.
  • Schema evolution, atomic renames and online index creation and removal.

Transactions and concurrency

  • Independent concurrent sessions and atomic transactions.
  • Savepoints, locking reads and optional deadlock detection.
  • Configurable wait limits, deadlines and cancellation.
  • Optional rollback of blocking transactions during online index publication.

Performance

  • Indexed query execution and automatic query planning.
  • Reusable application queries, streaming results and bulk loading.
  • Query planning and profiling tools for investigating slow queries.
  • Configurable memory use, compression and caching.

Durability and operations

  • Durable writes and crash recovery enabled by default.
  • Online backups, integrity checks and storage maintenance.
  • Raft replication with TCP/Unix snapshot cloning, asynchronous learner catch-up, voting promotion and optional bounded-staleness replica reads.
  • Permanent non-voting replicas and logs-only quorum voters for two materialized data copies plus a journal.
  • Durable replica reads from the previous certified barrier or a newly requested barrier.
  • Logical commit-position tokens in commit responses, replica visibility waits and per-query minimum positions.
  • Optional async Raft durability with periodic quorum flushes, COMMIT DURABLE barriers and explicit recovery to a certified stable prefix.
  • Schema inspection, database status and live lock diagnostics.
  • Actionable errors and tools for planning database changes.

Integration and tools

  • An embedded Go API with no external database server.
  • An interactive command-line interface and script execution.
  • A MySQL protocol server with TCP and Unix sockets, TLS and client certificate authentication, independent sessions and prepared statements.
  • PostgreSQL wire emulation with SCRAM authentication, prepared queries, TLS and client certificates.
  • Guides for application development, troubleshooting and database operations.

See the documentation for feature details and restrictions.

Quick start

Build from the repository root with Go 1.22.2 or newer:

go build -o slopdb .
./slopdb ./example-db

The getting started guide walks through creating a table, querying data and running scripts.

To connect using MySQL clients, run ./slopdb --mysql-tcp 127.0.0.1:3306 ./example-db or use --mysql-socket /tmp/slopdb.sock. See MySQL server for authentication, both-listener operation and compatibility limits.

For PostgreSQL clients, use ./slopdb --postgres-tcp 127.0.0.1:5432 ./example-db or --postgres-socket /tmp/slopdb-postgres/.s.PGSQL.5432. See PostgreSQL emulation for TLS, client certificates and SQL compatibility limits.

For replicated clusters, see Raft replication for bootstrap, clone/join, TLS, membership management and SQL read consistency options.

Using SlopDB from Go

The Go API supports querying, concurrent application sessions and transactions, with deadlines and cancellation. Options let applications choose resource and durability settings.

The embedded database/sql driver registers as slopdb: import _ "slopdb/driver", then call sql.Open("slopdb", directory). A pool uses independent sessions over one shared physical engine. NewConnector can also wrap an existing native database without taking ownership of it.

See prepared statements for parameter binding and transaction examples, and application operations for working with results, loading data, backups and integrity checks.

Tests and benchmarks

go test ./... -count=1 -timeout 10m
go test -race ./... -count=1 -timeout 10m
go vet ./...

The repository includes SQL reference fixtures, concurrency and transaction tests, corruption checks and crash-recovery tests. Ordinary Go tests use isolated temporary databases and require no external database engine. See TESTING.md for selective commands and coverage.

  • TPC-C-inspired load tester: concurrent transactional work, latency measurements and consistency checks.
  • TPC-H query runner: all 22 query shapes on DBGEN inputs, with complete-result verification.
  • Engine comparisons: SlopDB, SQLite and DuckDB.
  • Performance checks: repeatable measurements, microbenchmarks and CI artifacts.

These are development benchmarks rather than certified TPC scores. Compare runs with matching data, concurrency, execution mode and durability settings.
